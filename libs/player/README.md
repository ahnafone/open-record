# @open-record/player

Queue and playback for Open Record. Depends only on `@open-record/models`.

- `PlayerEngine` - pure queue/playback logic exposed as Angular signals
  (queue, current, status, position, duration, shuffle, repeat, error).
- `AudioEngine` port with two adapters:
  - `Html5AudioEngine` - web and fallback; OS controls via `navigator.mediaSession`.
  - `NativeAudioEngine` - Capacitor `capacitor-plugin-playlist` (background audio,
    lock-screen and notification controls).
- `MediaSessionController` - wraps `navigator.mediaSession` (web only; native
  engines own system controls).
- `PlayerService` + `providePlayer()` - Angular wiring.

## Usage

```ts
// app.config.ts
providePlayer({
  resolve: (track) => sourceRegistry.resolve(track), // TrackResolver
  skipOnError: true, // default
});

// component
readonly player = inject(PlayerService).engine;
this.player.setQueue(tracks, { startIndex: 2 });
```

The player never imports music-source. The app supplies a
`TrackResolver = (track) => Promise<PlayableSource>` via `providePlayer` (or the
`TRACK_RESOLVER` token). `AUDIO_ENGINE` can be overridden for tests.

Behaviour: previous restarts the track when more than 3s in; shuffle keeps the
current track first and the rest in a stable random order; repeat `one` only
affects natural track end (manual next still advances); failures set `error()`
and, with `skipOnError`, advance until every queued track has failed once.

## Native background audio: plugin choice

Chosen: **`capacitor-plugin-playlist@8`** (Capacitor 8 peer).

Why: it is the only Capacitor 8 option evaluated that provides a real
background playback service with lock-screen/notification **next and previous**.

- Android: Media3 ExoPlayer inside a `MediaSessionService` foreground service
  (`mediaPlayback` type). The plugin manifest merges the service,
  `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK` and `WAKE_LOCK`.
- iOS: `AVQueuePlayer` + `MPRemoteCommandCenter` / Now Playing info.

Alternatives evaluated:

| Plugin                                  | Why not                                                                                  |
| --------------------------------------- | ---------------------------------------------------------------------------------------- |
| `@capgo/capacitor-native-audio` 8.x     | Maintained, but no next/previous remote commands; no managed Android foreground service. |
| `@mediagrid/capacitor-native-audio` 3.x | Media3 service, but only seek forward/back on the lock screen.                           |
| `@jofr/capacitor-media-session`         | Capacitor 6 only, unmaintained.                                                          |
| `@capacitor-community/native-audio` 8.x | Sound-effect oriented, no media session.                                                 |

### How the adapter uses it

Queue logic stays in `PlayerEngine`. The native adapter loads a three-item
window `[previous, current, next]` so the OS can skip and auto-advance while the
WebView is suspended; `TRACK_CHANGED` to a neighbour is reported as
`onSkipped` and the engine re-centres the window. Repeat `one` sends no next.

URLs: `/_capacitor_file_/...` becomes `file://...`; bundled relative paths
become `asset:///public/...` on Android. On iOS bundled sources must be
absolute `file://` URLs.

If the plugin is not installed or not on a native platform,
`createAudioEngine()` falls back to `Html5AudioEngine`.

## Setup

- `capacitor-plugin-playlist@8` is installed and synced (`npx nx run app:cap-sync`).
- **iOS deployment target is 18.0** (required by the plugin):
  `IPHONEOS_DEPLOYMENT_TARGET` in `App.xcodeproj` and `CapApp-SPM/Package.swift`
  (regenerated by `cap sync` from the Xcode project).
- Android: `kotlin_version` is set in `apps/app/android/variables.gradle`; the
  plugin's Gradle file requires it (the host is on AGP 8).

## Platform config

Android (`apps/app/android/app/src/main/AndroidManifest.xml`) - applied:

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

On Android 13+ it is requested at runtime before the first native `play()`
(`notification-permission.ts`, once per app run) through a small app-local
plugin, `NotificationPermissionPlugin.java`, registered in `MainActivity`. A
denial never blocks playback; only the notification is hidden. Optional: a monochrome
notification icon and a Glide `AppGlideModule` for album art.

iOS (`apps/app/ios/App/App/Info.plist`) - applied:

```xml
<key>UIBackgroundModes</key>
<array><string>audio</string></array>
```

## Known limitations

- Native adapter is untested on device; its local typing matches the
  plugin's 8.0.0 `definitions.d.ts`. Android debug APK assembles; iOS not
  built here (Linux).
- Web: browsers may block autoplay; `play()` then leaves status `paused`
  until the user taps play.
